# Планы

Браузерное приложение для последовательностей задач. Квадраты соединяются направленными связями; ветки занимают отдельные строки, а дата события не влияет на статус. Несвязанные задачи без даты находятся в закреплённой нижней строке.

## Запуск

Для первого запуска из корня проекта выполните `docker compose up --build -d`; затем достаточно `docker compose up -d`. Интерфейс будет доступен на `http://localhost:5173`. Фронтенд запускается в контейнере через Vite: каталог `frontend/` подключён с локальной машины, поэтому изменения исходников появляются в браузере без пересборки контейнера. Запросы `/api` Vite передаёт контейнеру API; порты API и PostgreSQL на хост не открываются.

Зависимости фронтенда устанавливаются в отдельный Docker volume при запуске контейнера. После изменения `package.json` или lock-файла перезапустите фронтенд: `docker compose restart frontend`.

API создаёт таблицы при первом запуске. PostgreSQL использует официальный образ `postgres:16-alpine` и хранит рабочие файлы в `data/postgres/pgdata/` на хосте. Каталог исключён из Git и сохраняется при удалении контейнеров Compose. Разовые архивы прежней миграции лежат в `data/backup/`, но в запуске приложения не участвуют.

## Управление

- `+` в нижней строке создаёт квадрат без даты.
- Наведите на квадрат или откройте его клавишей Enter. В раскрытой карточке можно менять название, дату события и статус. Название сохраняется только по кнопке с галочкой или после подтверждения при выходе мыши; при выборе «Позже» черновик остаётся в поле до следующего открытия.
- `+ ←` и `+ →` создают связанные квадраты. `← связь` и `связь →` позволяют выбрать существующий квадрат. Нажатие на метку связи в карточке удаляет её.
- Связанная цепочка автоматически получает рамку «Секция N». Двойное нажатие на название в левом верхнем углу позволяет задать имя секции; Enter сохраняет, Escape отменяет. При разделении цепочки секции перестраиваются.
- Прокрутка перемещает схему по горизонтали и вертикали. Кнопка справа сверху переключает тему.

## API

`GET /api/graph` возвращает `{nodes, links, sections}`. `POST /api/nodes`, `PATCH /api/nodes/:id`, `DELETE /api/nodes/:id` управляют задачами. `POST /api/links` с `{sourceId,targetId}` и `DELETE /api/links/:id` управляют связями. `PATCH /api/sections/:id` с `{name}` сохраняет название секции; пустая строка возвращает номер. API отклоняет циклы и повторяющиеся связи. Статусы: `waiting`, `todo`, `done`, `cancelled`.
